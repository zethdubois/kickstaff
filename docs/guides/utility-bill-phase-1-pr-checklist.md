# Utility Bill ETL Phase 1 PR Checklist

Concrete file-level checklist for the first implementation PRs.

This checklist assumes Phase 1 from `docs/guides/utility-bill-etl-execution-checklist.md` and keeps scope tight: schema, storage adapter, manual intake path, and Moscow parser validation.

## PR 1 - Database foundation (Drizzle schema + migration)

Target outcome: database can represent intake documents, account mappings, and run metadata.

### Files to update

- `src/lib/server/schema.ts`
- `drizzle/*.sql` (new migration generated from schema changes)
- `drizzle/meta/*` (snapshot/journal updates generated by Drizzle)

### Checklist

- [ ] Add `utilityBillDocuments` table definition in `schema.ts`.
- [ ] Add `utilityAccountMappings` table definition in `schema.ts`.
- [ ] Add `utilityBillRuns` table definition in `schema.ts`.
- [ ] Add enum-like status columns for parse and run states (text + constrained values in app code).
- [ ] Add uniqueness/indexes:
  - [ ] (`vendor`, `sha256`) on documents
  - [ ] (`vendor`, `billReference`) nullable-aware uniqueness policy
  - [ ] (`vendor`, `serviceAccountNumber`) on mappings
  - [ ] (`vendor`, `period`) on runs
- [ ] Export inferred select/insert types for new tables.
- [ ] Generate migration with `pnpm db:generate`.
- [ ] Validate migration applies with `pnpm db:migrate`.

### Verification

- [ ] `pnpm check` passes.
- [ ] New tables and indexes visible in local Postgres.

## PR 2 - S3-compatible storage adapter and env contract

Target outcome: app can read/write utility artifacts to `https://t3.storageapi.dev`.

### Files to update

- `src/lib/server/storage.ts` (new)
- `.env.example`
- optional: `src/lib/server/*` helper modules if splitting config/constants

### Checklist

- [ ] Add storage adapter with `putObject`, `getObject`, `headObject`, and `listByPrefix`.
- [ ] Use S3-compatible SDK client with configurable endpoint.
- [ ] Add env vars to `.env.example`:
  - [ ] storage endpoint
  - [ ] region
  - [ ] access key
  - [ ] secret key
  - [ ] bucket name
- [ ] Keep all storage credentials server-only.
- [ ] Add object key builders for:
  - [ ] raw PDFs
  - [ ] parsed snapshots (optional)
  - [ ] output CSVs
  - [ ] error artifacts

### Verification

- [ ] Scripted smoke test uploads and reads a test object.
- [ ] Key naming format matches scope doc conventions.

## PR 3 - Manual intake script and dedupe guard

Target outcome: one PDF can be manually ingested into storage and indexed in DB idempotently.

### Files to add/update

- `scripts/ingest-utility-bill.ts` (new)
- `src/lib/server/utilityBills/intake.ts` (new helper module)
- `src/lib/server/db.ts` (only if needed for script-safe initialization)

### Checklist

- [ ] Add script entry in `package.json` (e.g., `utility:ingest`).
- [ ] Accept file path + vendor/city args.
- [ ] Compute `sha256`.
- [ ] Upload source PDF to storage key under `utility-bills/raw/...`.
- [ ] Insert document row with `parseStatus=received`.
- [ ] Enforce dedupe using existing (`vendor`, `sha256`) check.
- [ ] Return clear outcome (`ingested`, `duplicate_skipped`, or `failed`).

### Verification

- [ ] Running twice on same file skips second ingest.
- [ ] DB row and storage object metadata are consistent.

## PR 4 - Moscow parser v1 and parse persistence

Target outcome: parser extracts normalized fields from sample Moscow statement and stores parse output.

### Files to add/update

- `src/lib/server/utilityBills/parsers/types.ts` (new)
- `src/lib/server/utilityBills/parsers/moscow.ts` (new)
- `src/lib/server/utilityBills/parseDocument.ts` (new)
- `scripts/parse-utility-bill.ts` (new, for local parser testing)
- `docs/thirdparty/UtilityBill_sample.pdf` (existing fixture reference only)

### Checklist

- [ ] Define normalized parse result interface.
- [ ] Implement Moscow parser with anchor-based extraction.
- [ ] Extract at minimum:
  - [ ] service account number
  - [ ] bill reference
  - [ ] bill date
  - [ ] due date
  - [ ] service period start/end
  - [ ] current charges amount
  - [ ] service address
- [ ] Ensure current charges is chosen over total due.
- [ ] Update document row with parse fields + status (`parsed` or `failed`).
- [ ] Persist debug payload in `rawParseJson` for failure analysis.

### Verification

- [ ] Parser succeeds on `UtilityBill_sample.pdf`.
- [ ] Date and amount normalization are stable (ISO date + numeric amount).
- [ ] Failed parse path captures actionable `parseError`.

## PR 5 - Phase 1 hardening and sign-off

Target outcome: phase 1 is merge-ready and operationally testable.

### Checklist

- [ ] Add minimal integration test from ingest -> parse update.
- [ ] Add parser unit tests for currency/date extraction edge cases.
- [ ] Add concise operator run notes to scope/checklist docs.
- [ ] Run final `pnpm check`.
- [ ] Dry-run phase 1 flow on at least one real statement.

### Merge gate

- [ ] No duplicate ingest on repeated input.
- [ ] At least one statement parsed end-to-end with correct current charges.
- [ ] New schema and scripts documented in docs guides.
