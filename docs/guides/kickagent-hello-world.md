# Kickagent: Hello World Spec

**Purpose:** Define the first integration contract between `kickagent` (separate repo) and `publicweb` (wrapper/UI layer).

**Audience:** Developer implementing `kickagent.git`; this is the spec to fulfill.

---

## Overview

`kickagent` is a standalone Node.js package (npm module) that provides reusable business logic functions. `publicweb` imports kickagent and wraps its functions as console commands accessible via the KAM dev palette.

This spec defines the **first hello world function** that demonstrates:

- How kickagent functions accept context (user, logger)
- How they broadcast real-time progress via logger (not console.log)
- How they export structured results
- How publicweb will consume and wire them

---

## Function: `helloWorld`

### Location

`kickagent/src/hello.ts` (or equivalent)

### Signature

```typescript
/**
 * A simple hello world function demonstrating the kickagent pattern.
 *
 * @param userId - User ID from session context
 * @param userEmail - User email from session context
 * @param logger - KlogBroadcaster for real-time console output
 * @returns Promise<{ message: string }>
 */
export async function helloWorld(
  userId: string,
  userEmail: string,
  logger: KlogBroadcaster,
): Promise<{ message: string }>;
```

### Behavior

1. Accept three parameters: `userId`, `userEmail`, `logger`
2. Broadcast a log message via `logger.info()`:
   ```
   logger.info(`hello from kickagent (user=${userEmail})`);
   ```
3. Return an object with a message:
   ```typescript
   {
     message: `Hello, ${userEmail}!`;
   }
   ```
4. **Never** call `console.log()` or browser APIs; all output must go through the logger

### Example Implementation

```typescript
export async function helloWorld(
  userId: string,
  userEmail: string,
  logger: KlogBroadcaster,
): Promise<{ message: string }> {
  logger.info(`hello from kickagent (user=${userEmail})`);
  return { message: `Hello, ${userEmail}!` };
}
```

---

## KlogBroadcaster Interface

Your package must define this interface locally (do **not** import from publicweb):

```typescript
/**
 * Logger interface for kickagent functions to broadcast real-time progress
 * back to the KAM console. All function output must use this, never console.log.
 */
export interface KlogBroadcaster {
  /**
   * Log a message at 'log' level (general info).
   */
  log(msg: string): void;

  /**
   * Log a message at 'info' level (informational).
   */
  info(msg: string): void;

  /**
   * Log a message at 'warn' level (warning).
   */
  warn(msg: string): void;

  /**
   * Log a message at 'error' level (error).
   */
  error(msg: string): void;
}
```

### Why Define It Locally?

- Decouples kickagent from publicweb (no direct web framework dependency)
- Allows kickagent to be used in non-web contexts (CLI, scheduled jobs, etc.)
- publicweb provides a concrete implementation when calling kickagent functions

## Integration: How publicweb Will Use This

Once `helloWorld` is implemented in kickagent, publicweb will:

1. **Import the function:**

   ```typescript
   import { helloWorld, type KlogBroadcaster } from "kickagent";
   ```

2. **Register a console command** that wraps it:

   ```typescript
   registerCommand("hello", async (args) => {
     const result = await helloWorld(user.id, user.email, logger);
     return {
       log: result.message,
       level: "info",
     };
   });
   ```

3. **User runs** `hello` in the KAM console palette (Ctrl+/) and sees:
   - Real-time klog: `"hello from kickagent (user=alice@example.com)"`
   - Result message: `"Hello, alice@example.com!"`

✓ No direct dependency on publicweb or web frameworks  
✓ No console.log or browser APIs
